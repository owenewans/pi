Завершите работу.

Дополнительные инструкции: $ARGUMENTS

Сначала определите контекст по истории разговора.

Правила определения контекста:
- Если в разговоре уже упоминается задача GitHub или PR, используйте этот существующий контекст.
- Если работа началась с `/is` или `/pr`, считайте, что контекст задачи или PR уже известен из разговора и проведённого анализа.
- Если в истории разговора нет задачи GitHub или PR, считайте работу не связанной с GitHub.

Если я явно не переопределяю что-либо в этом запросе, выполните следующее по порядку:

1. Добавьте или обновите соответствующую запись журнала изменений пакета в разделе `## [Unreleased]` согласно правилам журнала изменений репозитория.
2. Если задача связана с задачей GitHub или PR и итоговый комментарий к задаче или PR ещё не публиковался в этом сеансе, составьте его в моём тоне, покажите предварительный вариант и опубликуйте ровно один итоговый комментарий. Комментарий должен заканчиваться этой точной отдельной строкой уведомления без каких-либо вариаций:

   ```text
   This comment is AI-generated by `/wr`
   ```
   Это обязательный литерал; смысл: «этот комментарий сгенерирован ИИ с помощью `/wr`».
3. Создайте коммит только из файлов, которые вы изменили в этом сеансе.
4. Если задача связана ровно с одной задачей GitHub, включите `closes #<issue>` в сообщение коммита. Если она связана с несколькими задачами, остановитесь и спросите, какую использовать. Если она не связана ни с одной задачей, не включайте `closes #` или `fixes #` в сообщение коммита.
5. Проверьте текущую ветку git. Если это не `main`, остановитесь и спросите, что делать. Не отправляйте изменения из другой ветки, если я явно этого не разрешу.
6. Отправьте текущую ветку.
7. Если задача связана ровно с одной задачей GitHub, после отправки явно закройте её с причиной `completed`, чтобы выполнились рабочие процессы закрытия задач в `.github/`. Это относится только к задачам, не к PR.
   - Проверьте `gh issue view <issue> --json state,stateReason,labels`.
   - Если задача открыта, выполните `gh issue close <issue> --reason completed`.
   - Если задача уже закрыта с любой причиной, кроме `COMPLETED`, сначала откройте её повторно, затем закройте командой `gh issue close <issue> --reason completed`, чтобы GitHub создал новое событие закрытия.
   - Если задача уже закрыта как `COMPLETED`, оставьте её закрытой, если только метка `inprogress` всё ещё не присутствует; в таком случае откройте её повторно и снова закройте с причиной `completed`.

Ограничения:
- Никогда не добавляйте в индекс несвязанные файлы.
- Никогда не используйте `git add .` или `git add -A`.
- Выполните обязательные проверки перед коммитом, если код изменился.
- Не открывайте PR без моей явной просьбы.
- Если работа не связана с задачей GitHub или PR, не публикуйте комментарий GitHub.
- Если итоговый комментарий к задаче GitHub или PR уже публиковался в этом сеансе, не публикуйте ещё один без моей явной просьбы.
- Пропускайте журнал изменений только тогда, когда работа нацелена на ветку, отличную от `main`. Для веток возможностей, рабочих деревьев и PR, нацеленных на `main`, записи журнала изменений обязательны.
