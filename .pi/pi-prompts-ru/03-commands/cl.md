Проверьте записи журнала изменений для всех коммитов с последнего релиза.

## Порядок работы

1. **Найдите тег последнего релиза:**
   ```bash
   git tag --sort=-version:refname | head -1
   ```

2. **Выведите все коммиты после этого тега:**
   ```bash
   git log <tag>..HEAD --oneline
   ```

3. **Прочитайте раздел [Unreleased] каждого пакета:**
   - packages/ai/CHANGELOG.md
   - packages/tui/CHANGELOG.md
   - packages/coding-agent/CHANGELOG.md

4. **Для каждого коммита проверьте:**
   - Пропускайте обновления журнала изменений, изменения только документации, служебные действия по выпуску релиза.
   - Пропускайте изменения сгенерированных каталогов моделей (например, `packages/ai/src/models.generated.ts`), если они не сопровождаются намеренным изменением продукта, видимым пользователям, в несгенерированном исходном коде или документации.
   - Определите, какие пакеты затрагивает коммит (используйте `git show <hash> --stat`).
   - Убедитесь, что в затронутых пакетах есть запись журнала изменений.
   - Для внешних вкладов (PR) проверьте формат: `Description ([#N](url) by [@user](url))`. Это обязательный шаблон формата; `Description` означает описание, `by` указывает автора.

5. **Правило дублирования между пакетами:**
   Изменения в `ai`, `agent` или `tui`, затрагивающие конечных пользователей, следует дублировать в журнале изменений `coding-agent`, поскольку coding-agent является пользовательским пакетом и зависит от них.

6. **Добавьте раздел New Features после исправлений журнала изменений:**
   - Вставьте раздел `### New Features` в начало `## [Unreleased]` в `packages/coding-agent/CHANGELOG.md`. `### New Features` является обязательным литералом заголовка и означает «новые возможности».
   - Предложите пользователю главные новые возможности для подтверждения перед их записью.
   - По возможности добавляйте ссылки на соответствующую документацию и разделы.

7. **Отчёт:**
   - Перечислите коммиты без записей.
   - Перечислите записи, требующие дублирования между пакетами.
   - Добавьте недостающие записи непосредственно в файлы.

## Справочник формата журнала изменений

Разделы (по порядку; заголовки являются обязательными литералами):
- `### Breaking Changes` — изменения API, требующие миграции.
- `### Added` — новые возможности.
- `### Changed` — изменения существующей функциональности.
- `### Fixed` — исправления ошибок.
- `### Removed` — удалённые возможности.

Указание авторства:
- Внутренний вклад: `Fixed foo ([#123](https://github.com/earendil-works/pi/issues/123))`. Смысл примера: «исправлено foo» со ссылкой на задачу.
- Внешний вклад: `Added bar ([#456](https://github.com/earendil-works/pi/pull/456) by [@user](https://github.com/user))`. Смысл примера: «добавлено bar» со ссылками на PR и автора.
