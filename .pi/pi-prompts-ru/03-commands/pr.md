description: Проверять PR по URL со структурированным анализом задач и кода
argument-hint: "<PR-URL>"

Вам даны один или несколько URL PR GitHub: $@

Для каждого URL PR выполните следующее по порядку:
1. Перед началом анализа добавьте PR метку `inprogress` через GitHub CLI. Если добавление метки завершится ошибкой, явно сообщите об этом и продолжайте.
2. Полностью прочитайте страницу PR. Включите описание, все комментарии, все коммиты и все изменённые файлы.
3. Найдите связанные задачи, упомянутые в тексте PR, комментариях, сообщениях коммитов или перекрёстных ссылках. Полностью прочитайте каждую задачу, включая все комментарии.
4. Проанализируйте diff PR без извлечения ветки PR в рабочую копию или переключения на неё. Используйте `gh pr diff`, `gh pr view`, `gh api` и локальные файлы основной ветки; если требуется содержимое файлов PR, используйте полученные ссылки с `git show <ref>:<path>` или временные файлы. Полностью прочитайте все соответствующие файлы кода без усечения и сравните их с diff. Не загружайте объекты файлов PR, если файл есть в main и контекст diff достаточен. Включите связанные пути выполнения кода, которые отсутствуют в diff, но нужны для проверки поведения.
5. Не проверяйте наличие записи в журнале изменений. Согласно CONTRIBUTING.md, PR от участников не должны менять `CHANGELOG.md` — сопровождающий добавляет запись при слиянии.
6. Проверьте, требуют ли изменений packages/coding-agent/README.md, packages/coding-agent/docs/*.md, packages/coding-agent/examples/**/*.md. Обычно это требуется при изменении существующих или добавлении новых возможностей.
7. Представьте структурированную проверку со следующими разделами; английские названия ниже являются обязательными литералами:
   - `What it does:` — что делает: один короткий абзац с описанием изменения и его цели.
   - `Good:` — хорошее: обоснованные решения или улучшения.
   - `Bad:` — плохое: конкретные проблемы, регрессии, недостающие тесты или риски.
   - `Ugly:` — серьёзные проблемы: тонкие или существенно влияющие проблемы.
   - `Tests:` — тесты: что покрыто, чего не хватает и достаточны ли существующие тесты.
   - `Open questions for you:` — открытые вопросы к пользователю: только то, что блокирует решение о слиянии и требует участия пользователя. Полностью опустите раздел, если таких вопросов нет.

Формат вывода для каждого PR (обязательные литералы заголовков сохранены):
PR: <url>
What it does:
- ...
Good:
- ...
Bad:
- ...
Ugly:
- ...
Tests:
- ...
Open questions for you:
- ...

Если проблем не найдено, укажите это в разделах `Bad` и `Ugly`.
