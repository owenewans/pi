argument-hint: "<issue>"

Проанализируйте задачи GitHub: $ARGUMENTS

Для каждой задачи:

1. При запуске в CI (`CI=true`) не добавляйте метку `inprogress` и не назначайте исполнителя задачи. Иначе перед началом анализа добавьте задаче метку `inprogress` через GitHub CLI и назначьте задачу локальному пользователю `gh`. Если какое-либо действие завершится ошибкой, явно сообщите об этом и продолжайте.
2. Полностью прочитайте задачу, включая все комментарии и связанные задачи и PR. Используйте поля, поддерживаемые GitHub CLI, например:
   ```sh
   gh issue view <issue> --json title,body,comments,labels,assignees,state,url,author,createdAt,updatedAt,closedByPullRequestsReferences
   ```
3. Не доверяйте анализу, приведённому в задаче. Независимо проверьте поведение и проведите собственный анализ на основе кода и пути выполнения.

4. **Для ошибок**:
   - Игнорируйте любой анализ первопричины в задаче (вероятно, он неверен).
   - Полностью прочитайте все связанные файлы кода (без усечения).
   - Проследите путь выполнения кода и определите настоящую первопричину.
   - Предложите исправление.

5. **Для запросов возможностей**:
   - Не доверяйте предложениям по реализации в задаче без проверки.
   - Полностью прочитайте все связанные файлы кода (без усечения).
   - Предложите наиболее лаконичный подход к реализации.
   - Перечислите затронутые файлы и необходимые изменения.

НЕ реализуйте изменения без явной просьбы. Только анализируйте и предлагайте.
